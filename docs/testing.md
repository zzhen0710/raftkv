# 测试策略与覆盖要求

生效：2026-10-19。当前为计划与验收要求，尚无项目测试工程、覆盖报告或工具执行结果。版本范围见 [ROADMAP](../ROADMAP.md)，实施方式见 [workflow](workflow.md)。

## 目标与选型

每小节随实现增加测试，每版本执行累计回归，最终全部自研模块都有可定位的行为验证。按风险选择单元/集成/故障测试；执行到一行不能替代正确断言，百分比也不能证明分布式协议正确。

Python 为适合场景的首选，采用 pytest 组织；本人正在学习 Python，首次出现的新机制在小节 note 中解释。需要直接检查 C++ 内部对象/状态时使用 C++ 测试，不为测试偏好建设额外语言绑定或复制一套 Raft 实现。

| 验证对象 | 首选方式 |
| --- | --- |
| 终端输入输出、退出状态 | Python + pytest 调用实际程序 |
| 多进程启动/退出/重启、临时数据目录、客户端请求 | Python + pytest |
| 故障场景编排、历史保存与小规模一致性检查 | Python；内部故障点由 C++ 提供 |
| KV 内部接口、Raft 状态转换、编解码 | C++ 单元测试 |
| RAII、移动语义、生命周期、内存问题 | C++ 测试及适用 sanitizer |
| 短写/同步失败等底层错误 | C++ 故障注入，Python 按需编排端到端验证 |

C++ 测试库在 S01 按工具链、依赖和学习成本选择并记录，不预先承诺某个未经验证的库。使用同一 CMake/CTest 构建与调度入口，Python 依赖在独立环境声明可复现版本；运行细节在工程建立后填入实际命令，不展示尚不存在的可执行入口。

## 行为覆盖与代码覆盖

行为要求：

- 全部自研模块有对应验证；按模块特征使用直接测试或集成测试，不强求每个薄包装单独造测试。
- 公开接口的成功、边界及声明的失败语义可定位到测试。必要的安全检查与协议/持久化不变量有针对性用例。
- 修复实质缺陷时增加能捕获它的回归测试；测试预期从契约独立推导。
- 保存重要故障的最小输入、种子和事件序列；无法覆盖的路径、环境限制与剩余风险明确记录。
- 测试和检查器也需审查。历史检查器等关键辅助逻辑使用已知合法/非法历史验证，不能把测试存在当作测试有效。

初始量化目标（项目目标，不是通用行业标准）：

| 范围 | 行覆盖率 | 分支覆盖率 |
| --- | ---: | ---: |
| KV、协议、编解码、恢复等核心逻辑 | 至少 90% | 至少 80% |
| 全部自研 C++ 代码 | 至少 85% | 至少 75% |

v0.1 首次报告后校准工具统计与范围，不能为了通过而随意降低目标或排除困难代码。关键错误路径必须单独验证，不能被总体百分比抵消。指标不要求所有行/分支均 100%，工具产生的编译器/异常相关分支应说明口径。

C++ 用编译器插桩及 gcov/等效工具统计；Python 脚本覆盖率单独看，不能替代 C++ 覆盖率。记录编译器、配置、统计范围、未覆盖项及原因；只合理排除第三方、生成文件和构建产物，不排除自研模块以美化数字。

全量数值应合并声明范围内测试的数据，避免只展示表现好的子集。被 kill 的进程可能未刷新覆盖数据，必须说明该类故障测试的统计限制，不把缺少数据误判为没有执行或已覆盖。

## 测试代码与 Python 学习

- 测试按“准备 → 执行 → 断言 → 清理”组织，名称表达行为。
- Python 注释与 docstring 说明场景意图、关键断言、生命周期、失败清理和不显然的语法。第一次使用 fixture、参数化、上下文管理器等时在 note 解释，不逐行重复翻译简单代码。
- 明确本人练习的核心断言与可委托的机械配置，保持程序易读；不用复杂框架掩盖测试逻辑。
- 正确性断言不依赖性能快慢；计时需求明确环境与容差，不随意放宽语义消除失败。

## 可靠执行与证据

- 子进程、连接、请求、条件等待都有截止时间；失败与超时也必须清理资源。只清理由当前测试创建/持有的进程和目录。
- 使用 pytest fixture/临时目录隔离数据，正常与异常路径都释放资源。并行测试明确端口与目录隔离，未解决隔离前不盲目开启并行。
- Python subprocess 使用参数列表，按需传环境，不通过 shell 拼接用户输入；检查退出状态，保存必要 stdout/stderr。
- 用明确就绪条件与有界轮询等待服务，不靠固定长 sleep 猜测；协议核心通过逻辑时间测试，不用真实等待替代可控模型。
- 随机测试固定并保存种子和事件轨迹。重复运行用于发现不稳定性，不通过无限重试、吞错、静默 skip/xfail 让失败变成功；临时排除需理由、影响范围和后续处理。
- 模拟短写/同步失败、实际 kill、网络故障与真实掉电分别陈述。单 VM 三进程不等于跨机器故障域验证。
- 快速单元/接口测试作为基础 CI；集成、故障和长测试分层引入。ASan/UBSan 与独立 TSan 配置按代码实际阶段启用，所用 C++20 特性由实际构建验证。
- 常规产物写忽略的 build/runs/work 目录；重要最小重现输入和人工总结提交到仓库，不上传整套运行数据或凭据。

工具与命令建立后，本文件持续补充实际入口、分组和已知缺口。当前不安装依赖、不创建空测试目录，也不把这些要求记为已经完成。
